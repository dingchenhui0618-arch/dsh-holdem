# 局域网模式：房间号不进广播，快照按座位视角

## 背景

需求是「同一网络里的其他安装可以加入这张桌，加入后随机顶替一名人机角色」，同时**不影响单机玩法**。
DSH 的 web 端口只监听回环（实测 `curl http://<LAN IP>:3080/` 拿不到响应），所以客人根本连不到宿主，
必须有插件自己开的端口；而每台机器又需要一种不需要用户抄 IP 的发现方式。

## 决定

- 每个浏览器会话可以开一个**房间**，房间服务绑在插件自己的端口上（默认 47811，`0.0.0.0`），
  发现走 UDP 广播（默认 47812）。**默认关闭**：不开启时不占端口、不发广播。
- 发现广播**只**包含房间标识、桌名、端口、人数与牌局状态——**不含房间号**。
  同网络的人能看到"这里有一张牌桌"，但只有被口头告知 6 位房间号的人能加入。
- 加入时用房间号换一个 **ticket**（32 字节随机），之后所有请求带 ticket；
  房间号或 ticket 不对一律拒绝。
- 顶替一名人机 = 把该座位 `kind` 从 `ai` 改成 `guest`。引擎的 AI 调度本来就用
  `p.kind !== 'ai'` 拦住，所以引擎不需要新增分支；`releaseSeat` 再把 `kind` 改回 `ai` 并唤醒 AI。
- 快照改成 **按观看者座位**生成：`snapshot(viewerSeat)`。只有 `p.seat === viewerSeat` 的底牌会下发
  （摊牌与"非摊牌收池只给赢家"的既有规则不变）。客人因此只看得见自己的牌，**主机也看不见客人的牌**。
- 客人掉线由 20 秒 TTL 兜底：座位交还人机并唤醒 AI，牌局不会卡在等一个人。
- 加入方本地插件充当代理：它去主机取快照、把动作转发回去，自己这台机器的界面照常读本地 API，
  所以客户端不需要知道牌局在远端。

## 后果

- 局域网只影响显式开启的房间；`test/lan.test.mjs`、`test/lan-room.test.mjs` 覆盖房间号、
  广播编解码、防泄牌与座位交还，其余 71 项单机测试不受影响。
- 首次开启需要用户在 Windows 防火墙弹窗里点「允许访问」；这一步无法自动化，README 写明了。
- 企业/访客网络可能屏蔽客户端之间的广播，因此保留「手动填 IP:端口」的兜底路径。
- 同一台机器上跑两个实例时，第二个实例绑不到固定的发现端口：广播仍能发出，
  但发现能力降级（`discovery: 'degraded'`），手填地址仍可用。
